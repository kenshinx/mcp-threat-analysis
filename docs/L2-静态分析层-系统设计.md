# L2 静态分析层 · 系统设计

> 上位文档：[[恶意 MCP 检测可执行技术方案]] §4
> 目标读者：L2 层开发负责人
> 本文是面向开发的子系统设计，不重复整体方案中的论证。

---

## 1. 职责与边界

### 1.1 职责

对单个 `(server_id, version)` 输入物（package tarball / git snapshot / docker image / remote 元数据）执行**静态、单文件可达**的全部检测，并产出 `findings` 行。

### 1.2 输入 / 输出

| 项 | 内容 |
|---|---|
| **输入** | `ScanTarget`：`{server_id, version, artifact_type, artifact_path, primary_lang, declared_metadata}` |
| **输出** | `List[Finding]` 写入 `findings` 表，`layer='L2'` |
| **副产物** | `static_summary` 缓存（供 L3 复用）：`{tool_handlers, call_graph_local, io_summary, string_literals, manifest_facts}` |

### 1.3 不在 L2 范围内

- 跨文件 / 跨函数语义判别 → L3
- 工具间组合分析 → L3
- 任何 LLM 调用 → L3
- 任何动态执行 → L5
- 版本 / 时间维度对比 → L4

L2 只看**单一 artifact 的当前快照**。

## 3. 子模块设计

### 3.1 orchestrator

```python
class L2Orchestrator:
    def run(self, target: ScanTarget) -> L2Result:
        workdir = self.loader.prepare(target)            # 解压、拉取
        summary = self.extractors.run(workdir, target)   # 通用静态摘要
        findings = []
        for analyzer in self.enabled_analyzers(target):
            try:
                findings.extend(analyzer.analyze(workdir, summary, target))
            except AnalyzerTimeout as e:
                emit_ops_metric("l2.timeout", analyzer.name)
            except Exception:
                logger.exception("analyzer crashed", analyzer=analyzer.name)
        self.persistence.save(target, findings, summary)
        return L2Result(findings=findings, summary=summary)
```

要点：
- 每个 analyzer 独立沙箱（子进程 + 时间预算）
- 单 analyzer 失败不影响整体；记录到运维指标
- `static_summary` 只在所有 analyzer 完成后落地，避免脏读

**任务粒度**：以 `(server_id, version_id)` 为幂等单位；同 input 重复执行 = noop（先查 `findings.artifact_ref` 是否已写过该 detector）。

### 3.2 target_loader

输入：`artifact_type ∈ {npm_tarball, pypi_wheel, docker_image, github_archive}`

行为：
- 下载到本地（已被 L0 归档时直接 `s3://` 拉取）
- 解压到隔离临时目录（限制 file count / 总大小，防 zip-bomb）
- 输出 `WorkDir(root_path, primary_lang, lang_files: dict[lang, list[Path]])`
- 归一化：`tsx → typescript`、`mjs/cjs → javascript`、`pyi` 跳过

### 3.3 extractors

#### 3.3.1 ast_extractor

用 tree-sitter（Python/TS/JS/Go/Java 优先支持）抽出每个 tool handler 的：

```python
@dataclass
class ToolHandler:
    name: str
    declared_description: str | None
    declared_input_schema: dict | None
    file: Path
    span: tuple[int, int]
    callees_local: list[str]               # 本文件内调用
    callees_imported: list[ImportRef]      # 跨文件 / 第三方
    string_literals: list[str]
    io_summary: IOSummary                  # 见下
```

```python
@dataclass
class IOSummary:
    network_calls: list[NetworkCall]      # {func, url_arg_kind: literal|var|tainted, line}
    file_ops: list[FileOp]                # {func, path_arg_kind, mode, line}
    subprocess_calls: list[SubprocessCall]
    env_reads: list[str]
    fs_writes: list[FileOp]
    crypto_calls: list[str]
```

入口识别（`tool_handler_locator`）：
- Python: `@mcp.tool()` / `@server.tool()` / `FastMCP().tool()`
- TS/JS: `server.setRequestHandler('tools/call', ...)` 内 switch / `tool('name', ...)` 调用
- Go: `mcp.RegisterTool` 等 SDK 函数（参考 go-sdk）

未识别到 handler 时退化为「全文件扫描」，`tool_name=null`。

#### 3.3.2 string_extractor

汇总所有字符串字面量 → `string_literals`，并分类：
- URL（提取 host）
- email
- 文件路径
- 高熵串（`shannon_entropy ≥ 4.5 且 len ≥ 50`）

供 `obfuscation_analyzer` 与 manifest_analyzer 复用。

### 3.4 SemgrepAnalyzer

**目录布局**：
```
rules/semgrep/
├── self/
│   ├── code/
│   │   ├── cmd_injection.yaml
│   │   ├── path_traversal.yaml
│   │   ├── ssrf.yaml
│   │   ├── dynamic_exec.yaml
│   │   ├── sensitive_file_access.yaml
│   │   ├── hardcoded_secret.yaml
│   │   ├── undeclared_egress.yaml
│   │   └── obfuscated_base64_exec.yaml
│   ├── text/
│   │   ├── bcc_silent_exfil.yaml
│   │   └── prompt_injection_extras.yaml      # 多语种补丁
│   └── manifest/
│       ├── postinstall_network.yaml
│       └── publisher_repo_mismatch.yaml
└── translated_from_cisco/
    ├── tool_poisoning.yaml
    ├── coercive_injection.yaml
    ├── prompt_injection.yaml
    ├── credential_harvesting.yaml
    ├── data_exfiltration.yaml
    ├── system_manipulation.yaml
    ├── command_injection.yaml
    ├── code_execution.yaml
    ├── sql_injection.yaml
    └── script_injection.yaml
```

**翻译规则约定**（`translated_from_cisco/*.yaml` 文件头）：
```yaml
# Translated from: cisco-ai-defense/mcp-scanner@<commit>:mcpscanner/data/yara_rules/tool_poisoning.yara
# Translation date: 2026-04-26
# Original LICENSE: Apache-2.0 (see LICENSES/cisco-mcp-scanner-NOTICE)
```

**调用方式**：
```python
class SemgrepAnalyzer(Analyzer):
    name = "semgrep"
    def analyze(self, workdir, summary, target):
        rule_paths = self._select_rules(target.primary_lang)
        proc = subprocess.run([
            "semgrep", "--json", "--quiet",
            "--config", *rule_paths,
            "--metrics=off",
            workdir.root_path
        ], timeout=self.timeout, capture_output=True)
        return self._parse_findings(proc.stdout, target)
```

**规则范围控制**：
- `code/` 规则只跑代码文件
- `text/` + `translated_from_cisco/` 通过 `paths.include` 限定到 `**/*.{py,ts,js,go,md,json}` + 字符串字面量子集
- `manifest/` 只跑 `package.json / pyproject.toml / server.json`

**Finding 转换**：
```python
def _to_finding(self, hit) -> Finding:
    return Finding(
        detector=f"semgrep:{hit.check_id.split('.')[-1]}",
        layer="L2",
        issue_code=hit.metadata.get("issue_code"),  # 'CWE-78' / 'E001' / etc.
        severity=hit.severity.lower(),
        confidence=hit.metadata.get("confidence", 0.7),
        evidence={
            "file": hit.path,
            "line": hit.start.line,
            "snippet": hit.extra.lines,
            "tool_name": resolve_tool_name(hit.path, hit.start.line, summary),
        },
    )
```

### 3.5 CodeQLAnalyzer

仅对 `language ∈ {python, javascript, typescript, java, go}` 启用，覆盖 Semgrep 数据流弱点：

- query suite：`security-extended` + 自研 `mcp-tool-arg-taint.ql`（把 `tool_argument` 标为 source）
- 通过 CLI 异步生成 SARIF → 解析 → Finding

**降级策略**：CodeQL 数据库构建失败 / 超时 ≥ 10min → 跳过，发 ops 告警，但不阻塞流程。

### 3.6 SecretAnalyzer

并行调用：
- TruffleHog（`--only-verified=false`，包括未验证；评分时按 verified 加权）
- Gitleaks（默认规则集）

**去重**：以 `(secret_kind, sha256(secret), file:line)` 为 key。
**严重等级**：
- verified secret → critical
- 高熵但未验证 → medium
- 低熵 placeholder → low / info

### 3.7 SCAAnalyzer

- npm 项目：`npm audit --json`
- pypi 项目：`pip-audit --format=json --strict`（基于 `requirements.txt` / `pyproject.toml`）
- 通用：`osv-scanner --json --recursive`

合并去重；按 `(package, version, advisory_id)` 主键。

**输出额外字段**：`evidence.cvss`, `evidence.advisory_url`, `evidence.fix_version`。

### 3.8 ManifestAnalyzer

针对 `package.json / pyproject.toml / server.json` 的检测点（jsonschema + 自研规则组合）：

| 检测点 | 严重 |
|---|---|
| `bin` 指向网络下载脚本 | high |
| `scripts.postinstall` / `setup.py:install` 含网络/exec | critical |
| 声明 repo URL 与 publisher 不一致 | medium |
| `keywords` 含 mcp 但无 SDK 依赖 | low（伪 MCP） |
| `publishConfig.registry` 私有 | info |
| `server.json` 字段缺失 / 类型异常 | low |

实现：
```python
class ManifestAnalyzer(Analyzer):
    def analyze(self, workdir, summary, target):
        findings = []
        for path in workdir.find(["package.json", "pyproject.toml", "server.json"]):
            data = self._safe_load(path)
            for rule in self.rules_for(path.name):
                hit = rule(data, path, summary)
                if hit:
                    findings.append(hit)
        return findings
```

### 3.9 ReputationAnalyzer

输入：SCA 结果中的依赖列表
查询：
- npm registry：`weekly_downloads`, `first_publish_at`, `maintainers`
- libraries.io：`stars`, `forks`, `dependents_count`
- PyPI JSON API：类似字段

阈值（初版，可调）：
| 信号 | 严重 |
|---|---|
| 周下载量 < 50 且依赖被工具直接使用 | medium |
| 包发布 < 30 天且无历史版本 | medium |
| publisher 账号注册 < 30 天 | high |
| 单一 maintainer 且不在主流贡献网络 | low |

**缓存**：声誉数据 TTL 24h，避免每次扫描重复查询。

### 3.10 ObfuscationAnalyzer

- 高熵字符串密度（`high_entropy_count / total_strings`）
- AST 模式：`exec/eval/Function` 套 `b64decode/atob/fromCharCode`
- minified-only 文件比例（无 sourcemap、单行 > 5000 chars）
- packed pattern：`!function(){}(...)` 嵌套深度

输出 `obfuscation_score: 0..1`，>0.3 触发 finding。该分数也写入 `static_summary`，供 L4 算 delta。

## 4. 数据契约

### 4.1 Finding（L2 层共用）

```python
@dataclass
class Finding:
    detector: str            # 'semgrep:<rule>', 'codeql:<query>', 'secret:trufflehog', ...
    layer: Literal["L2"]
    issue_code: str | None   # 'CWE-78' / 'E001' / 'W008' / ...
    severity: Literal["info","low","medium","high","critical"]
    confidence: float        # 0..1
    evidence: dict           # {file, line, snippet, tool_name?, ...}
    artifact_ref: str        # f"{registry}:{package}@{version}" or sha256
```

不引入 `cwe / aitech` 多列字段（按当前主方案保持单列 `issue_code`）。

### 4.2 StaticSummary（供 L3 复用）

```python
@dataclass
class StaticSummary:
    target: ScanTarget
    tool_handlers: list[ToolHandler]
    string_literals: list[str]
    declared_egress_domains: list[str]   # 来自 manifest 中声明
    obfuscation_score: float
    manifest_facts: dict
    sca_dep_list: list[Dependency]
```

L3 通过 `static_summary` 表读取（按 `target` 主键 upsert），避免重复 AST 解析。

### 4.3 数据库

复用主方案 §3.1 的 `findings` 表。

新增 `static_summaries` 表（L2 ↔ L3 缓存）：
```sql
CREATE TABLE static_summaries (
    server_id    UUID,
    version      TEXT,
    summary      JSONB,
    written_at   TIMESTAMPTZ,
    PRIMARY KEY (server_id, version)
);
```

## 5. 性能与运行约束

| 项 | 目标 |
|---|---|
| 单 target 端到端 | P50 < 60s, P95 < 5min |
| Semgrep 超时 | 5min |
| CodeQL 超时 | 10min（失败可降级） |
| 工作目录大小上限 | 200MB（artifact 解压后） |
| analyzer 并发 | orchestrator 内部串行，跨 target 通过 worker 横向扩展 |

**幂等性**：以 `(server_id, version, detector_name)` 为 finding 写入幂等 key；重跑前先 soft-delete 上次同 key 的 finding（保留 `superseded_at`）。

## 6. 错误处理

| 错误 | 处理 |
|---|---|
| artifact 拉取失败 | retry 3 次，仍失败 → 整 target 标记 `l2_status=fetch_failed`，不写 finding |
| 解压超限 | 直接拒绝；标记 `quarantined` |
| 单个 analyzer crash | 记 ops，继续其他 analyzer |
| Semgrep 规则语法错误 | CI 阶段拦截，运行时 panic |
| LLM 不在本层使用 | N/A |

## 7. 与上下游接口

### 7.1 上游（来自 L1）

L1 在 `package_versions` 写入新版本后，通过任务队列发送：
```json
{
  "kind": "l2_scan",
  "server_id": "...",
  "version": "1.0.16",
  "registry": "npm",
  "artifact_url": "s3://mcp-archive/packages/npm/...",
  "primary_lang": "typescript"
}
```

### 7.2 下游（递交给 L3）

L2 完成后发送：
```json
{
  "kind": "l3_scan_ready",
  "server_id": "...",
  "version": "1.0.16",
  "static_summary_ref": "static_summaries[...]"
}
```

L3 立即可读 `static_summaries` 与 `findings(layer=L2)`。

### 7.3 下游（递交给 L6）

L2 在每条 finding 写入后即可被 L6 增量聚合；不需要等全部 analyzer 完成。

## 8. 测试策略

| 类型 | 内容 |
|---|---|
| **规则单测** | 每条 Semgrep 规则配 `*.test.{py,ts,...}` 正例 / 反例 |
| **CodeQL 回归** | 已知 CVE 仓库快照（如 Anthropic git MCP CVE）作为黄金集 |
| **集成测试** | postmark-mcp v1.0.16 + 5 个良性 Server，跑全 L2 比对 finding 集合 |
| **性能基线** | 100 个真实 npm/pypi MCP 包做 P50/P95 跑批 |
| **回归** | 每次规则变更 CI 跑黄金集，禁止 precision/recall 跌落 |

## 9. 开发顺序建议

1. `target_loader` + `models` + `persistence`（骨架）
2. `extractors`（ast_extractor + string_extractor）
3. `SemgrepAnalyzer`（先跑 self/code 自研规则）
4. 翻译 Cisco YARA → Semgrep 规则（按文件逐条 PR）
5. `SecretAnalyzer` + `SCAAnalyzer`（成熟工具，集成快）
6. `ManifestAnalyzer`
7. `ObfuscationAnalyzer` + `ReputationAnalyzer`
8. `CodeQLAnalyzer`（最重，最后接入）
9. orchestrator 联调 + 集成测试
